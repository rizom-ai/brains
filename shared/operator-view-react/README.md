# Operator view React

Shared operator-view behavior for Studio and Dashboard. Providers supply semantic blocks; hosts supply controls and choose appropriate presentation.

## Build and styles

Run `bun run build` in this package before consuming it. The workspace build graph does this through dependency builds; Studio's standalone UI builder also builds this dependency. `bun run test` builds first.

The runtime export is `dist/index.js`; TypeScript resolves the source types. The package compiles StyleX before either host imports it, including source-based Dashboard development. SSR therefore needs neither a DOM nor a StyleX loader. Tests also exercise the built entry under production React without a loader.

The build compiles StyleX once and collects static rules, then embeds them into the compiled JavaScript as `operatorViewStylexCSS` and writes `dist/stylex.css`. Dashboard includes the immutable export in its stylesheet; Studio includes the file in `app.css`. No browser style injection is needed for migrated components. On the pinned Bun 1.4.0, the build automatically runs its compiler in an isolated non-JIT subprocess: large StyleX compilations otherwise trigger a media-tokenizer EOF bug. This does not disable JIT in callers, tests, or app runtimes. Recheck and remove this version-scoped workaround when upgrading Bun.

Migration is incremental: facts, notices, cards, columns, lists, record typography, totals, reading panes, source text, filters, pagination, text links, identity headers, mastheads, section tabs/panels, page framing, and footers have compiled styles. Other renderer components still use `operatorViewRendererStyles` until migrated. Fonts and colors continue to use existing console tokens.

## Shared chrome

`OperatorHeader`, its link/button controls, `OperatorMasthead`, and `OperatorSectionTabs`/`OperatorSectionTab` provide token-based, statically styled chrome. Hosts retain ownership of destinations, accessible labels, IDs, and navigation behavior. Section tabs use native anchors for no-JavaScript navigation and style their `aria-selected` state; no runtime class translation or style injection is required. Header links have 44px phone targets. Supplementary header buttons remain available on phones unless the host explicitly supplies `desktopOnly`.

`OperatorPage`, `OperatorFrame`, `OperatorCanvas`, and `OperatorSections` compose the responsive reading frame. `OperatorSection` preserves native section attributes and honors `hidden`; `OperatorSectionHeading` stays visible until the enclosing host marks its tabs with `data-ui-tabs-active`. Hosts still own enhancement, focus, hashes, and panel selection. `OperatorFooter` and `OperatorFooterLink` retain host-authored identity, version, and destinations, with 44px phone links. Replaced Dashboard framing and footer CSS is removed rather than layered beneath compiled classes.

`OperatorPanel` frames host-composed content with a shared heading, optional source copy or direct accessory, and bounded inline-size containment. Its standard inset adapts to phones; `tight` reduces phone insets for dense content, while `flush-bottom` supports an edge-aligned tail. `OperatorPanelGrid` supplies the two-column-to-single-column reading layout. Dashboard uses these for public summaries, maps, system cards, and widget frames; their former global card/header CSS and the unused class-based `CardHeader` export are removed. Provider-composed semantic cards continue to use `OperatorCard`.

Panel bodies compose `OperatorPanelParagraph`, `OperatorPanelStatus`, `OperatorPanelEmpty`, and `OperatorPanelList`/`OperatorPanelListItem`. Hosts supply status copy, destinations, badges, and semantic tones; shared styles never classify workspace or source IDs. Linked summaries retain native navigation, visible focus, hover accents, and 44px phone targets. Long badges and copy remain bounded. `OperatorStats` also offers a `ledger` presentation with four desktop columns and two phone columns, independent of host density. Dashboard's former overview stylesheet is removed; its filtering, ordering, deduplication, limits, and empty states remain host-owned.

`OperatorColumns` offers a `panels` presentation for primary cards and a native supporting aside: two primary columns and a vertical aside on desktop, three supporting columns on tablet, and single columns on phones. `OperatorPanel.fullWidth` spans its containing grid. `OperatorFacts` supports a `reference` presentation and authored numeric/React values, retaining native exact timestamps and zero counts. `OperatorStatusDot` and `OperatorStatusList` style explicit good/warn/error tones; hosts retain labels, availability interpretation, ordering, and limits. Dashboard uses these for System layout, reference facts, and public availability, with the replaced selectors deleted. `OperatorStatusSummary`, `OperatorReadiness`, `OperatorSteps`, `OperatorChecks`, and `OperatorStatusPill` provide the remaining snapshot content. Readiness is binary rather than a fabricated percentage; checks retain native table headers and keep update metadata visible on phones. `OperatorStats` has a three-column-to-stacked `band` presentation paired with flush-bottom panels, with independently supplied caption tones. Panels offer explicit neutral/good decorative washes, and panel paragraphs support a supporting `note` presentation. Dashboard's entire System stylesheet is removed; host-owned health interpretation, exact operation names, full diagnostics, counts, and visibility boundaries remain unchanged.

## Provider-owned hierarchy

List blocks may declare `presentation`: `standard`, `editorial`, `attention`, or `activity`. These are reading roles, not workspace identities. Editorial titles use the existing display face at 20px; attention uses 18px UI type with stronger emphasis on the leading item; activity uses 14px UI type. Explicit roles work in both host densities. Attention records group metadata and links beneath the copy; ordinary records keep dates inline, while activity puts dates on a separate line. Routine row actions use the host's `link` button variant; confirmation-gated actions remain `danger`. Master-detail collections retain two-line summaries, and timestamps retain their exact source values in `<time>` markup.

Cards may declare `presentation: "feature"` for a primary state with a prominent display heading, or `presentation: "disclosure"` for supporting details that start closed. Card metadata supplies compact section facts without repeating the heading. Action controls may override display `label` without changing their declared identity, inputs, permissions, or confirmation. Their full contents and permission-filtered controls remain available. Providers own these choices; Studio does not dispatch to plugin-specific renderers. Shared components do not require identical workspace compositions.

Query blocks can contain filters, pagination, or both. Providers can place a pagination-only block below a collection. A single page shows its range without redundant buttons; a previously populated later page keeps a way back after its items disappear. Comfortable filters use plain labels and a bounded two-column phone layout; compact hosts retain their instrument labels.

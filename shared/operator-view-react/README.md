# Operator view React

Shared operator-view behavior for Studio and Dashboard. Providers supply semantic blocks; hosts supply controls and choose appropriate presentation.

## Build and styles

Run `bun run build` in this package before consuming it. The workspace build graph does this through dependency builds; Studio's standalone UI builder also builds this dependency. `bun run test` builds first.

The runtime export is `dist/index.js`; TypeScript resolves the source types. The package compiles StyleX before either host imports it, including source-based Dashboard development. SSR therefore needs neither a DOM nor a StyleX loader. Tests also exercise the built entry under production React without a loader.

The build compiles StyleX once and collects static rules, then embeds them into the compiled JavaScript as `operatorViewStylexCSS` and writes `dist/stylex.css`. Dashboard includes the immutable export in its stylesheet; Studio includes the file in `app.css`. No browser style injection is needed for migrated components. On the pinned Bun 1.4.0, the build automatically runs its compiler in an isolated non-JIT subprocess: large StyleX compilations otherwise trigger a media-tokenizer EOF bug. This does not disable JIT in callers, tests, or app runtimes. Recheck and remove this version-scoped workaround when upgrading Bun.

Renderer presentation is compiled: hosts include `operatorViewStylexCSS`. The legacy renderer stylesheet and `operatorViewRendererStyles` export have been removed; internal consumers now use the single compiled asset. Fonts and colors continue to use existing console tokens. Studio-owned editor/chrome placement also compiles in Studio's static asset; host-level document rules and scoped CodeMirror vendor selectors remain separate.

## Shared chrome

`OperatorHeader`, its link/button controls, `OperatorMasthead`, and `OperatorSectionTabs`/`OperatorSectionTab` provide token-based, statically styled chrome. Hosts retain ownership of destinations, accessible labels, IDs, and navigation behavior. Section tabs use native anchors for no-JavaScript navigation and style their `aria-selected` state; no runtime class translation or style injection is required. Header links have 44px phone targets. Supplementary header buttons remain available on phones unless the host explicitly supplies `desktopOnly`.

`OperatorPage`, `OperatorFrame`, `OperatorCanvas`, and `OperatorSections` compose the responsive reading frame. `OperatorSection` preserves native section attributes and honors `hidden`; `OperatorSectionHeading` stays visible until the enclosing host marks its tabs with `data-ui-tabs-active`. Hosts still own enhancement, focus, hashes, and panel selection. `OperatorFooter` and `OperatorFooterLink` retain host-authored identity, version, and destinations, with 44px phone links. Replaced Dashboard framing and footer CSS is removed rather than layered beneath compiled classes.

`OperatorPanel` frames host-composed content with a shared heading, optional source copy or direct accessory, and bounded inline-size containment. Its standard inset adapts to phones; `tight` reduces phone insets for dense content, while `flush-bottom` supports an edge-aligned tail. `OperatorPanelGrid` supplies the two-column-to-single-column reading layout. Dashboard uses these for public summaries, maps, system cards, and widget frames; their former global card/header CSS and the unused class-based `CardHeader` export are removed. Provider-composed semantic cards continue to use `OperatorCard`.

Panel bodies compose `OperatorPanelParagraph`, `OperatorPanelStatus`, `OperatorPanelEmpty`, and `OperatorPanelList`/`OperatorPanelListItem`. Hosts supply status copy, destinations, badges, and semantic tones; shared styles never classify workspace or source IDs. Linked summaries retain native navigation, visible focus, hover accents, and 44px phone targets. Long badges and copy remain bounded. `OperatorStats` also offers a `ledger` presentation with four desktop columns and two phone columns, independent of host density. Dashboard's former overview stylesheet is removed; its filtering, ordering, deduplication, limits, and empty states remain host-owned.

`OperatorColumns` offers a `panels` presentation for primary cards and a native supporting aside: two primary columns and a vertical aside on desktop, three supporting columns on tablet, and single columns on phones. `OperatorPanel.fullWidth` spans its containing grid. `OperatorFacts` supports a `reference` presentation and authored numeric/React values, retaining native exact timestamps and zero counts. `OperatorStatusDot` and `OperatorStatusList` style explicit good/warn/error tones; hosts retain labels, availability interpretation, ordering, and limits. Dashboard uses these for System layout, reference facts, and public availability, with the replaced selectors deleted. `OperatorStatusSummary`, `OperatorReadiness`, `OperatorSteps`, `OperatorChecks`, and `OperatorStatusPill` provide the remaining snapshot content. Readiness is binary rather than a fabricated percentage; checks retain native table headers and keep update metadata visible on phones. `OperatorStats` has a three-column-to-stacked `band` presentation paired with flush-bottom panels, with independently supplied caption tones. Panels offer explicit neutral/good decorative washes, and panel paragraphs support a supporting `note` presentation. Dashboard's entire System stylesheet is removed; host-owned health interpretation, exact operation names, full diagnostics, counts, and visibility boundaries remain unchanged.

## Map presentation

`OperatorMapFrame`, `OperatorMapCanvas`, `OperatorMapGraphic`, `OperatorMapCoordinates`, and `OperatorMapEmpty` provide compiled map framing, responsive SVG sizing, decorative coordinates, and full-width empty states. Frames support an explicit split layout, joined edge, and ambient background; tall graphics preserve their separate phone crop. Hosts own SVG geometry, descriptions, IDs, focus/selection, and supporting controls. `OperatorMapSummary` pairs three native definition lists with a host-supplied status and tone, keeping zero values and all source totals intact. Its inline numerals preserve the original line-box spacing. Dashboard's replaced frame, canvas, summary, and empty-state selectors are removed. Registered visualization components continue to own their rendering rather than being wrapped in a second map frame.

`OperatorMapIndex` and `OperatorMapIndexItem` retain host-owned ranking, counts, IDs, and selection. Index styling follows `aria-pressed` rather than a mirrored active class; phone controls have 44px targets and full labels remain in native text/title attributes. Guidance stays in normal flow so dense lists and remainder copy cannot overlap it. `OperatorMapLegend`, `OperatorMapLegendItem`, and `OperatorMapLegendNote` accept explicit marker shapes and tones. Dashboard interprets its source vocabulary and category precedence; shared styles never inspect category labels or IDs. The old index and legend selectors are deleted, and the host enhancer no longer mirrors button ARIA state into a styling class.

`OperatorMapGroup`, `OperatorMapPath`, `OperatorMapCircle`, `OperatorMapText`, and `OperatorMapCount` provide native SVG elements with compiled paint, type, and keyframes. Hosts pass presentation, tone, emphasis, and dimming explicitly; the shared layer never interprets point categories, statuses, IDs, coordinates, or path data. Region contours follow the host group's `data-map-active` state, independently of button ARIA state. Reduced motion stops animations while leaving marks visible and contours drawn. Dashboard's entire `maps.css` is removed; registered visualizations still own their separate rendering.

Dashboard lays out its selected territory labels within SVG bounds, avoiding label collisions without moving nodes or contours. Visible abbreviation respects grapheme boundaries and uppercase width; exact source labels remain in SVG titles/accessibility names and the native index. Source totals and the independent territory/index/label limits remain unchanged.

`OperatorTabStrip`, `OperatorTabButton`, and `OperatorTabCount` own line-tab presentation. Selection and count paint follow native `aria-selected`, including hover; hosts retain IDs, panels, routing, and keyboard behavior. Strips scroll within narrow panels at every viewport, phone targets are 44px, focus rings remain inside the scroll area, and reduced motion disables transitions. Both the shared renderer's static tabs and UI-library `WidgetTabs` compose these compiled elements. The replaced Dashboard line-tab rules are deleted. Run `CONSOLE_CHROMIUM_PATH=… bun scripts/widget-tab-regression.ts` to check the real SSR composition and enhancer across both climates and three viewport sizes.

`OperatorChoiceGroup`, `OperatorChoiceButton`, `OperatorChoiceLabel`, and `OperatorChoiceCount` provide pill-style choices; selected paint follows `aria-selected` for tabs or `aria-pressed` for filters. Compact spacing and attention counts are explicit props. `OperatorChoiceTools`, `OperatorChoiceSearch`, and `OperatorChoiceToggle` provide native filter tools with 44px phone targets, bounded long labels, visible focus, and reduced-motion transitions. Native `[hidden]` remains authoritative. UI-library owns search text, the twelve-option initial limit, active-option retention, all-value semantics, rows, and empty states; it no longer supplies styling classes for selected/gap states. The old pill/filter selectors are deleted. The browser regression also checks both tab variants and search, overflow, hiding, empty-state, and row restoration behavior across twelve viewport/climate/variant combinations.

`OperatorActionLinks` and `OperatorActionLink` supply compiled navigation-group/link presentation without interpreting destinations, external-link behavior, or labels. Hosts provide emphasis and decorative indicators explicitly. UI-library preserves its exact hrefs and target/rel semantics while composing these native elements. Long labels remain complete and bounded, phone links have 44px targets, keyboard focus is visible, and indicator hover motion respects reduced-motion transitions. Replaced widget action selectors are deleted; the browser regression exercises these links alongside tabs and filters.

`OperatorSummaryList` and `OperatorSummaryItem` provide native unordered lists and bounded copy/trailing columns for host-composed widget records. Titles follow the standard 16px/500 hierarchy, descriptions use 12px, and metadata uses 11px mono; full string headings remain in native titles when visually ellipsized. `OperatorSummaryMetadata`, `OperatorSummarySeparator`, `OperatorSummaryTags`, and `OperatorSummaryTag` preserve host-authored segments, order, and full tag text. Zero descriptions and trailing values retain their own slots. Native hiding remains authoritative under filtering. `OperatorStatusPill` adds explicit `presentation="label"` and muted tone support; UI-library owns its existing status-tone mapping. Dashboard's entire widget-primitives stylesheet is deleted, including the unused list-count rule. Browser checks cover real filtered list compositions with long copy/tags/statuses, exact metadata, zero values, and bounded columns.

`OperatorDocumentBody` supplies the native console body, typography, background, and climate-aware grain/vignette through compiled StyleX. String-rendered app hosts use `operatorApplicationDocumentClasses()` for their body, mount, and boot message, preserving the app-specific flex frame and quieter grain. Hosts still own the HTML document, climate state, and content; fixed decorative layers remain non-interactive. Dashboard foundation CSS retains only its document reset. Registered-widget invalid-data, empty, and pending messages compose `WidgetEmptyState` through `OperatorPanelParagraph`’s muted presentation, preserving source-owned wording and conditions. Standalone site sections include the immutable `operatorViewStylexCSS` exported by UI-library; no runtime style injection or legacy `.muted` selector is needed. Unused pre-WidgetTabs compatibility selectors, old column entrance animations, and obsolete theme-button overrides are removed rather than translated.

The CSS renderer’s segmented tabs compose `OperatorSegmentedGroup` and `OperatorSegmentedButton`. These preserve the bounded inset frame and native ARIA-driven selected paint, with 44px phone targets, inset keyboard focus, and wrapping for long labels. The renderer retains count formatting, active-panel selection, and callbacks; providers do not style tab IDs. List filters use the same shared native controls across hosts rather than repurposing action buttons. Their renderer retains custom all-values, item membership, source counts, and empty-state conditions. Contract `gap` emphasis maps explicitly to attention presentation while retaining the original diagnostic attribute; selected and hovered attention controls keep their warning paint.

Action-form field labels and CSS-host input/select presentation are compiled StyleX. App hosts retain their native control adapters; query-select styling remains independent. Inputs use the configured console UI font, bounded widths, and 44px phone targets. Checkbox labels provide the phone target without enlarging the native check itself. Defaults, validation, conditional labels, secret suppression, and submission remain renderer-owned behavior.

Studio list and matrix items may supply `actionsLabel` for their grouped row-action trigger; cards with `presentation="disclosure"` may supply `disclosureLabel` to keep the heading and metadata visible beside a separate trigger. Both labels are validated provider text, not renderer-inferred workspace semantics. Action-menu labels are removed when permission narrowing removes all actions. Omitted labels retain the generic menu/native-heading presentation. Labeled cards use the host disclosure adapter, preserving full content, action inputs, disabled state, and dialog/native disclosure behavior.

`OperatorDisclosure` supplies native details/summary with an explicit action presentation. Its marker and spacing follow the immediate parent’s native `open` state, so nested disclosures remain independent. CSS hosts preserve edited fields across toggles; app hosts retain their dialog adapter. Other disclosure presentations remain unchanged. Browser checks cover Enter activation, focus, phone targets, long labels, nesting, and form-state retention.

Action-result panels also use compiled StyleX: native definition lists, bounded values with full native titles, wrapping headings/labels, and stacked phone facts. Copy buttons retain host presentation and exact values, with nonshrinking 44px phone targets. Result projection remains unchanged: undeclared, missing, and nonscalar fields are omitted; zero, false, null, and sensitive markers retain their existing meaning. The browser harness mounts the production renderer and exercises the actual result/copy path with a synthetic clipboard stub.

Action-form layout is compiled too. Primary forms retain two bounded tracks; phone forms and forms inside the named `operator-aside` container use one. Sidebar width remains full-width, and submit controls retain end/start alignment. The sidebar container replaces legacy-class selector coupling without changing the column markup or pulling portaled dialogs into sidebar layout.

CSS-host action and confirmation buttons reuse app-ui-react controls instead of emitting unstyled `btn` classes. Control adapters accept `xstyle`, composing presentation overrides with base declarations instead of concatenating competing atomic classes. Native events, disabled states, confirmation focus/cancellation, and host adapters remain intact; row text actions retain their existing presentation. Shared buttons wrap long labels and respect reduced motion, including primary hover translation.

Table framing, cells, alignment, current-row paint, and compact-row switching now use compiled StyleX. The renderer still owns columns, row order, scalar formatting, links, actions, and compact eligibility. Only source-annotated rows become phone records; ordinary rows remain in a bounded scrolling table. Action alignment is an explicit layout input, not a descendant-class override. The browser fixture covers mixed, fully annotated, and unannotated tables and invokes a real row action with its exact input.

The Dashboard CSS audit removes retired stats/stat, filter-summary, alignment-class, group, and notice-modifier selectors: production renderers no longer emit them. Action groups also own their complete layout in StyleX. That audit preceded the remaining renderer consolidation; both renderer/Dashboard legacy sheets are now removed. Studio-owned placement hooks are still retained where consumed; an emitted marker class alone does not prove its CSS is redundant.

Meters and progress now use compiled native-element styles, including browser progress tracks/fills, tone text, labels, details, and exact timestamps. Providers still own values, maximums, units, states, and bar availability; zero remains visible. Native bars receive their authored labels as accessible names. Card meters retain two bounded columns through a shared card-body structural attribute, not a legacy class selector. Dashboard-only meter padding/weight overrides and invalid border/surface token rules are removed in favor of the shared presentation.

Flow stations, connecting lines, captions, and details now compile through StyleX. Native `data-status` drives paint without generated state classes; ordered steps and `data-direction` remain provider-owned. Stations have bounded wrapping widths and a scrolling desktop track with room for the active halo; phones retain the vertical track. Card caption suppression uses the shared card-body attribute, and host caption typography slots remain supported. Chromium tests relational state paint, status changes, final-station line suppression, card scope, and overflow; Happy DOM covers native structure and source text.

`OperatorNotice` is exported for shared notice composition. Notice prose remains bounded to 4,000 characters; each disclosed diagnostic record uses the same 100,000-character bound as source text blocks, without clipping its content. Its compiled styles now own the complete left-rule frame, zero outer borders/radius, density gutters, and inherited action color. The remaining Dashboard box/paragraph overrides and legacy notice class are removed. Compact gutters use physical properties consistently so they override the base frame. Both densities and all tones are checked, including untitled copy without a phantom caption gap; browser fixtures retain exact action destinations and real renderer diagnostics/disclosure behavior.

Spatial figure/canvas framing, SVG and point-layer positioning, boundaries, zones, relationship strokes, and radial center labels now compile through StyleX. The renderer retains Cartesian/radial calculations, radii, viewBox/scaling, relationship admission, and full labels. Existing relationship tone precedence is unchanged. The remaining headings/status, action feedback, empty states, link placement, and matrix cells are compiled too. Renderer confirmations reuse the shared app UI modal, with explicit outside-dismiss policy and viewport portals that escape sidebar containers. No second dialog styling/focus implementation remains.

## Provider-owned hierarchy

List blocks may declare `presentation`: `standard`, `editorial`, `attention`, or `activity`. These are reading roles, not workspace identities. Editorial titles use the existing display face at 20px; attention uses 18px UI type with stronger emphasis on the leading item; activity uses 14px UI type. Explicit roles work in both host densities. Attention records group metadata and links beneath the copy; ordinary records keep dates inline, while activity puts dates on a separate line. Routine row actions use the host's `link` button variant; confirmation-gated actions remain `danger`. Master-detail collections retain two-line summaries, and timestamps retain their exact source values in `<time>` markup.

Cards may declare `presentation: "feature"` for a primary state with a prominent display heading, or `presentation: "disclosure"` for supporting details that start closed. Card metadata supplies compact section facts without repeating the heading. Action controls may override display `label` without changing their declared identity, inputs, permissions, or confirmation. Their full contents and permission-filtered controls remain available. Providers own these choices; Studio does not dispatch to plugin-specific renderers. Shared components do not require identical workspace compositions.

Query blocks can contain filters, pagination, or both. Providers can place a pagination-only block below a collection. A single page shows its range without redundant buttons; a previously populated later page keeps a way back after its items disappear. Comfortable filters use plain labels and a bounded two-column phone layout; compact hosts retain their instrument labels.

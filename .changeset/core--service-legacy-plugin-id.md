A first-party service package converted from a class can keep the plugin id its class had, as a first-party entity package already can, so its template, job and channel names stay those brains and queued jobs use; a service that owns one type installs it under the type itself. Only the canonical brain's composer names it. An interface package asking for a legacy id is refused with an error that names the package, where it named none before.

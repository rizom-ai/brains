# @brains/social-media

Social posts: short posts drafted for LinkedIn, generated by AI, kept as markdown and published through the content pipeline.

## Usage

The package default-exports a declarative entity package. The canonical brain composes it under the plugin id `social-media`, so its templates, data source and job keep the names sites and queued jobs use (`social-media:linkedin`, `social-media:posts`, `social-post:generation`):

```typescript
import socialMediaPackage from "@brains/social-media";
```

Settings:

```yaml
plugins:
  social-media:
    linkedin:
      accessToken: ${LINKEDIN_ACCESS_TOKEN} # publishes to LinkedIn when set
      organizationId: ${LINKEDIN_ORGANIZATION_ID} # post as an organization
    autoGenerateOnBlogPublish: true # draft a LinkedIn post for each queued blog post
```

## Writing posts

The package registers no tools of its own. `system_generate` writes a post with `social-post:generation`:

- from text and a title, as given;
- from text alone, shaped and titled by the AI;
- from a blog post or deck it shares, by its title and text;
- from a prompt.

The AI writes as the anchor, in the brain's voice, through `social-media:linkedin`. A title that is taken is asked for again, and a post whose id is taken lands beside it. A post asked to have an image queues its graphic once written. `system_create` saves a post as written; one with a title alone is a LinkedIn draft.

When the content pipeline schedules a social post, the generation shares a published blog post that no social post was written from yet, one of the five most recent.

## Social post

A post's body is its text. Its frontmatter is its metadata:

```yaml
---
title: Plugin System Launch # for file naming, not posted
platform: linkedin
status: draft # generating | draft | queued | published | failed
coverImageId: optional-image-id
documents:
  - id: optional-pdf-document-id
publishedAt: "2025-03-01T10:00:00.000Z" # set when published
platformPostId: "urn:li:share:1" # set when published
sourceEntityId: source-deck-id
sourceEntityType: deck # post | deck
---
Post content here...
```

Its slug is its platform and title (`linkedin-plugin-system-launch`). The error a failed publish recorded stays on the record, not in the file.

## Publishing, site and AT Protocol

- With a LinkedIn access token, the content pipeline publishes queued posts to LinkedIn: text, an image from `coverImageId`, or a native PDF/document post from `documents[]`. The post records `platformPostId` and `publishedAt`.
- `social-media:social-post-list` and `social-media:social-post-detail` render posts through `social-media:posts`: every post, unpublished then newest published first, or one by its slug.
- Each post is published as an `ai.rizom.brain.socialPost` record.

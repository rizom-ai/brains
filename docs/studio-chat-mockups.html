Studio workspace study · September 2026

Chat as a working room, not an app inside Studio.

A native conversation workspace shaped by Studio’s editorial grammar: sessions at left, the active exchange as the single scroll region, and authorized working context at right. The screen makes ongoing work, approvals, and generated artifacts legible without turning every event into a chat bubble.

00 Principles 01 Working room 02 Context handoff 03 Approval + jobs 04 Mobile sequence 05 Bounded states
01

One host, one grammar

Studio owns the route, title, responsive composition, and browser history. Chat does not arrive with a second masthead or nested app shell.

02

Conversation is a document

Messages read as an annotated working record. Roles sit in the margin; sources, actions, and artifacts remain structured material.

03

Context stays inspectable

The working set is visible beside the exchange, but it is secondary and collapsible. Source permission is never implied by the screen.

04

Durable work survives navigation

Approvals are explicit and jobs advertise that they continue. Re-entry restores server-owned progress rather than a browser-only illusion.

Host-owned

  • Studio route and browser history
  • Active session and panel state
  • Responsive composition and labels
  • Presentation copy and empty states

Chat-owned

  • Conversation and message persistence
  • Access and source disclosure checks
  • Streaming, uploads, approvals, and jobs
  • Structured server-owned lifecycle state

Prototype constraints

One active content scroll region per destination, 44px interaction targets, safe-area composer padding, no iframe or mounted standalone application, and no public UI controller.

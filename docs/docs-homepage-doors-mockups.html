Design notes

How the three doors stay in sync

Every block on the page is generated from exactly one source. Use Show sources (bottom right) to see which. The only prose written for the homepage itself is the hero and the three door definitions in site.ts.

Block Source Changes when
Hero, door titles and for-lines sites/docs/src/site.ts Rarely; the doors are the site's structure
Release status Package version at build time Every release, with no edit
Guide cards Guide frontmatter: door, persona, summary, recipe A guide is added or rewritten
Reference rows, index, counts docs-manifest.yaml: door, order, description A doc is added, moved or retitled
Door opener when no guide exists First doc in that door by order Disappears once a guide names the door
Project links site.ts, pointing at the repo files Never; the files move with the repo

The manifest entry gains two fields and loses one:

- id: getting-started
  title: Getting Started
  door: run                # replaces section
  order: 10
  description: Install the CLI, create a brain, and start it locally
  source: packages/brain-cli/docs/getting-started.md
  • Descriptions are explicit. The README's one-line descriptions move into the manifest, which replaces the first-paragraph extraction that cuts mid-word today. docs:check can require one per entry.
  • The index doc leaves the site. /docs/index repeats the homepage by hand. The README can stay as the GitHub entry point, generated from the same manifest, or shrink to a pointer to docs.rizom.ai.
  • Doors show a short list; the index shows everything. Each door lists its first few docs by order. The index below lists every guide and doc once, so nothing is curated twice.
  • Two dead links get fixed. Roadmap now points at the repo file, as /docs/index already does. The self-hosting guide shows as planned until it exists.

Brains documentation

A brain is one place for what you know.

It captures from where the work already happens, keeps it as plain markdown files you own, and answers from them in chat, in Studio, or from Claude and ChatGPT. It runs on a server you control, and the code is open source.

Version 0.2.0 is an alpha. See what stable still needs.

Where to start

Use a brain

Someone has set one up for you, or you will.

First step

Open the welcome email from your brain and set up a passkey. Then work wherever suits you: chat, Studio, or your AI tools.

Guides

  • The writerYears of essays and a folder of drafts, most of it still in Google Docs.
  • The researcherNotes, papers and saved links in apps that never talk to each other.

Run a brain

For yourself, or for the people moving in.

First step

$ bun add -g @rizom/brain
$ brain init my-brain --recipe personal
$ cd my-brain
$ brain start

Set AI_API_KEY in .env first. The brain prints a setup link for your passkey.

Extend a brain

Sites, themes and plugins, or the framework itself.

First step

  1. Configure the instance in brain.yaml
  2. Edit content in brain-data/
  3. Layer CSS in src/theme.css
  4. Change site structure in src/site.tsx
  5. Write a plugin when behavior or data must change

Use the smallest layer that solves the problem.

About this mockup

The hero says what a brain is, in wording from the team brain's capability menu and one-pagers. The figure is the writer guide's own example: a note becomes a draft post, shown as the real files.

Each door gives one concrete first step, then its guides, then its reference docs. Every doc appears once, so there is no separate index.

Kept in sync from three places: hero, door names and first steps in site.ts; guides from guide frontmatter (door, summary); reference lists from docs-manifest.yaml, which gains door and loses section.

Not live yet: the Running your own brain guide (/guides/self-hosting is a 404). Extend uses the Customization Guide as its walkthrough. Roadmap moves to the footer and points at the repo, replacing the 404 at /docs/roadmap.

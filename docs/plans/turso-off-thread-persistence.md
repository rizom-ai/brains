## Current slice: owned HTTP upload receipts and cancellation

1. Keep Bun's existing WebView renderer. The source actor now renders PNG or PDF from `index.html`, assets and a required strict `render.json` instruction. Instruction reads are regular-file/no-follow, capped at 128 bytes even if the file grows, and closed before rendering. Serving, SDK buffers, hashing and writes stay in that actor; no separate Chromium factory.
2. `FileProcessOwner.produce` admits one bulk producer within its existing two-child limit and joins actual Bun exit. The 100 MiB output ceiling, 32 KiB writes, no-replace publication and failed staging retention remain. Static inputs are size-checked before bounded stream reads; SDK/native/browser peak memory is not established.
3. Deck carousel joins blog/project printable and blog/project/deck OG providers on the shared file-only provider. Its 20-slide cap precedes theme/producer acquisition; theme resolution runs per request, is joined on cancellation, and retains site-info fallback behavior. Carousel filenames, brand labels, CSS and dark default remain. Controllers prepare textual metadata; referenced assets use owned downloads (at most 16 references). Failed staging is retained. Unused buffered composer capture/PNG/PDF APIs are removed after their last caller migrated; SDK injection remains actor-local. PDF retains CSS page sizing, backgrounds, signature validation and the 25 MiB ceiling within the global 100 MiB limit.
4. `SourceImageRenderJobHandler` consumes the borrowed PNG, compares actor inspection against the attachment's required SHA-256/size/MIME receipt, and publishes through `saveProcessedEntity({ fileAsset, signal })`. No buffered resolution or controller image preparation remains. Publication/reuse guards survive provider cleanup, uncertain publication and admitted target failures; cancellation before target admission returns an explicit warning without retracting the image.

5. `DocumentGenerationJobHandler` now sets its publication guard before submitting its save. Uncertain save replies and downstream target/progress failures preserve the saved document; pre-save rendering failures still mark pending documents failed. Distinct render/failure-update causes are aggregated with the original cause retained; identical failures are not wrapped twice. This is a safety boundary, not the document storage cutover.

6. Explicit named inspection artifacts extend the existing file capability: `files.inspect(source, { inspector: "pdf", signal })`. Names/configuration are bounded; missing selections fail before native authority acquisition and never fall back to the default image inspector. The PDF actor allocates only after authenticated transfer credit, copies borrowed chunks, verifies the signature and returns page-count metadata with the native-verified digest/size. Native retirement and actual actor exit remain joined. The existing counting heuristic is preserved: zero means unknown, not structural validity. Its buffer/string/GC peak is not claimed to fit the logical 100 MiB input ceiling.

This capability is required, not an optional buffered fallback; existing test collaborators reject unexpected loans.

8. Added the actor-side single-attempt HTTP(S) PUT implementation and IPC artifact (`shared/db/src/turso-worker/file-http-put*.ts`). It validates bounded metadata/headers and regular-file size before requesting, sends serial <=32 KiB chunks within the 100 MiB input limit, checks the full digest and file stability, and returns only status/digest/size metadata. Request, response, socket and file retirement are joined. Response bodies are destroyed without buffering; redirect/error statuses are returned without automatic replay. Cancellation cannot retract submitted bytes. The actor accepts cooperative cancellation and does not discard an already acknowledged result. Private/loopback reachability and normal TLS verification remain intact; native/TLS/kernel peak allocations remain unproven.

9. `FileProcessOwner.put` uses an explicit `httpUploadUrl` within the existing two-child admission. Submitted HTTP work receives cooperative cancellation, including during owner shutdown; validated late receipts are observed rather than discarded. Acknowledged receipts are held through actual actor exit and are not retracted by later cancellation. Ordinary file actors retain their existing termination behavior. Protocol faults still force fencing/termination; missing or malformed HTTP receipts fence reuse even after cancellation. Cancellation and actor failures preserve distinct causes. HTTP metadata types are exported through the owner boundary, and final status validation is shared with the actor.

What the annotations mean

1

Follow-ups are a new affordance class. They navigate with item context and never mutate: Discuss in chat opens the registered web-chat interaction with the composer prefilled (never auto-sent), Capture as note opens an unsaved CMS note using same-origin navigation state, and Open source entity already exists. Missing route or create capabilities hide their launch instead of guessing.

2

Facets replace the open-mail desk's special filters. After a source is selected, its bounded facets appear (mail: category, mail-priority, needs-reply). Stable filters become linkable while paging stays transient, so widgets can target …/inbox?sourceId=mail-items&facet.needs-reply=true.

3

Kind-specific follow-ups are source-declared links. Draft reply appears only on needs-reply mail and points into the draft-and-approve pipeline from email-reply-drafting.md. Candidates would declare Review profile / Invite; stale opportunities Open lead. Different items, different launches.

4

Resolution stays exactly as shipped — source-owned, confirmation-gated, re-listing. The visual split makes the contract legible: the top group starts something, the bottom group ends this.

5

Recognizable and connected mail. A verified, normalized email identity becomes a structured Inbox contact with its local Auth personId; the registered Admin interaction opens that exact person. Unknown senders remain sanitized name + domain text, never an address or inferred person. Thread position stays an independent idempotent ordinal. View original resolves the opaque ref through its private locator, fetches bounded plain text, and renders it once with no-store semantics. The same source-read primitive is consumed by email-reply-drafting.md.
